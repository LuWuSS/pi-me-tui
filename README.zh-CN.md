# pi-me-tui

[![CI](https://github.com/LuWuSS/pi-me-tui/actions/workflows/ci.yml/badge.svg)](https://github.com/LuWuSS/pi-me-tui/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

[English](README.md) | [简体中文](README.zh-CN.md)

为 Pi coding agent 提供的可配置多行状态栏。设计目标是把 `ccstatusline-zh` 的数据密度和显示效果带进 Pi：58 个可自由组合的组件、3 行默认布局、Powerline 主题、全局样式覆盖，以及 `/me-tui` 交互式配置界面。

## 功能

- 3 行默认状态栏，组件可增删（插入到选中项之后）、复制、排序、换行、搜索、编辑文字前缀
- 9 大类共 58 个组件：核心、Git、Token、速度、上下文、会话、环境、自定义、布局
- Powerline：7 套内置主题、自定义分隔符、起止端点、背景反转、自动对齐
- 全局样式覆盖：前景色、背景色、粗体、暗色、发光、内边距方向（全局值优先于组件级设置）
- 终端选项：颜色级别、图标模式、刷新间隔、Git/自定义命令/终端宽度缓存
- 配置导入/导出，导入时展示差异和新增 Shell 命令并要求确认
- 缓存命中率、输入/输出/总速度、上下文进度条、Git ahead/behind、工作树信息
- `/me-tui` 打开后重新安装本扩展的 footer，避免被其他 footer 扩展覆盖

## 安装

从 GitHub 安装（推荐）：

```bash
pi install git:github.com/LuWuSS/pi-me-tui
```

从 npm 安装（如果已发布）：

```bash
pi install npm:pi-me-tui
```

从本地目录安装：

```bash
git clone https://github.com/LuWuSS/pi-me-tui.git
pi install ./pi-me-tui
```

临时试用（不写入设置）：

```bash
pi -e ./pi-me-tui
```

安装后重启 Pi，状态栏会自动出现。输入 `/me-tui` 打开配置界面，升级用 `pi update`。

## 默认布局

默认使用中文、3 行：

```text
供应商: ... │ 模型: ... │ 思考: ... │ 分支: ... 变更: ...
上下文: [████░░░░] 12.5% │ 压缩: 2      本次输入: ... 本次输出: ... 本次总量: ... │ 缓存: ... 命中: ... | ↑/s ... ↓/s ... Σ/s ...
时钟: ... │ 本轮: ... │ 总时长: ... │ 对话: ... │ 调用: ... │ 会话: ... │ 内存: ... │ 技能: ... │ 目录: ...
```

左右两组之间的空白由 flex 组件撑开，右对齐内容在任意宽度下都贴边。所有组件都可以在 `/me-tui` 中替换、移动或删除；「恢复默认」会回到这套布局。

## 配置界面

`/me-tui` 主菜单：

- 编辑状态栏：管理行和组件，添加、复制、删除、移动、搜索、编辑前缀、组件选项；添加后按 Esc 返回组件列表和分类继续添加；`r` 可从分类中选择其它组件原位替换
- Powerline 设置：启用、主题、分隔符、背景反转、起止端点、自动对齐
- 全局样式：颜色、粗体、暗色、发光、内边距、图标、颜色级别、伸缩模式
- 速度显示为紧凑 `t/s`（如 `8.44kt/s`、`51.6t/s`），用 `↑/s`、`↓/s`、`Σ/s` 区分输入、输出、合计，避免与 Token 图标混淆
- 颜色从列表选择（默认、主题色、命名色、自定义 hex/rgb/ansi）；最大宽度填 0 表示不限制
- 设置面板用 `customMessageBg` 铺满整个终端高度，背后的对话内容不会透出来
- 选项高亮即预览（颜色、图标集、语言、主题、前缀、宽度），Enter 确认、Esc 返回；不必先保存再看效果
- 设置页占满终端、预览宽度与状态栏一致；全局粗体/暗色/发光/内边距与 Powerline 分隔符都会即时预览
- 粗体会同时提亮前缀和值；发光在此基础上再提亮 70%。行对齐可按行设置为默认（按分隔）/靠左/居中/靠右
- 终端与刷新：刷新间隔、Git 缓存、自定义命令缓存、终端宽度缓存
- 导出配置：写入 JSON 文件
- 导入配置：预览差异；新增 Shell 命令会完整展示，默认取消
- 恢复默认

快捷键：

| 按键 | 功能 |
| --- | --- |
| `↑` `↓` | 导航 |
| `Enter` | 选择/确认 |
| `a` | 添加组件 |
| `d` | 删除组件 |
| `m` | 移动模式，`↑`/`↓` 调整，`Enter` 完成 |
| `e` | 编辑文字前缀，`Tab` 恢复默认，留空隐藏 |
| `w` | 组件选项 |
| `h` | 隐藏状态/空值行为 |
| `/` | 在当前行内按名称搜索组件 |
| `q` | 返回上一层 |
| `Tab` | 切换行 |
| `n` / `x` | 新增行 / 删除当前行 |
| `q` | 退出 |

## 组件

### 核心（3）

供应商、模型、思考力度。

### Git（19）

分支、变更、新增、删除、状态、已暂存、未暂存、未跟踪、冲突、超前/滞后、SHA、Origin 所有者/仓库、Upstream 所有者/仓库、是否 Fork、根目录、工作树、工作树模式、工作树名称、工作树分支。

- 分支支持 OSC8 可点击链接（根据 origin URL 生成，GitLab 使用 `/-/tree/` 路径）
- 超前/滞后来自 `git status --porcelain=v1 --branch` 的 `[ahead N, behind M]`
- 工作树信息来自 `git worktree list --porcelain`
- 未安装 `gh`/`glab`，因此 PR 与 CI 组件暂未提供（按需求延后）

### Token（9）

本次输入、本次输出、本次缓存、本次缓存命中率、合计输入、合计输出、合计缓存、合计缓存命中率、合计 Token。若供应商不返回缓存数据，只要有使用量，缓存组件会显示 `0` / `0%`，而不是直接消失。

缓存命中率 = 缓存读取 ÷（输入 + 缓存读取）。pi-ai 归一化后，`input` 已扣除缓存读/写，因此分母正好等于完整 prompt（`input + cacheRead + cacheWrite`），OpenAI Chat / OpenAI Responses / Anthropic 口径一致。

“本次”默认指当前 agent run（最后一条用户消息之后）；可在终端选项中切换为“最后一轮”。合计指整个 session。

“本次”类组件在数值为 0 时默认隐藏（会话刚开始时底栏更干净）；在组件选项里把「空值隐藏」关掉即可始终显示。

### 速度（6）

本次输入、本次输出、本次总速度；合计输入、合计输出、合计总速度，单位为紧凑 `t/s`（如 `8.44kt/s`、`51.6t/s`），并带 `↑/s`、`↓/s`、`Σ/s` 前缀。

三个速度不是同一个分母：

- 输入速度 = 提示词 Token ÷ TTFT，提示词 Token = `input + cacheWrite + cacheRead`（即供应商实际收到的完整 prompt）
- 输出速度 = 输出 Token ÷ 解码耗时，解码耗时 = 响应总耗时 − TTFT
- 总速度 = 总 Token ÷ 响应总耗时

TTFT = 请求开始到首个 `text` / `thinking` / `toolcall` 内容块的耗时，由 `message_update` 实时采集。TTFT 不会写入 session 文件，因此 `pi -c` 恢复的会话没有样本，输入/输出速度改用响应总耗时估算，而不是直接不显示；非流式响应同理。总速度始终可计算。合计速度 = Σ Token ÷ Σ 时间，不是各条速度的平均值；`toolResult` / `compaction` 的 usage 只计入 Token 总量，不参与速度计时。

### 上下文（5）

上下文长度、上下文百分比、可用百分比（默认按 80% 可用窗口计算）、进度条。

进度条支持 `progress`、`progress-short`、`slider`、`slider-only` 四种模式。

### 会话（7）

会话时钟、会话名称、技能、对话轮数、模型调用次数、本轮会话时长、总会话时长。一轮从用户发送消息开始，到该轮最后一条回复结束；只有产生过助手回复的轮次才计入轮数。模型调用次数按助手消息计数（每次模型响应一条）。总会话时长是所有轮次时长之和，不含轮次之间的空闲时间。技能组件显示最近一次或最近列表中的 skill / MCP / 扩展工具调用。

### 环境（3）

当前目录、终端宽度、系统内存。

### 自定义（4）

自定义文本、自定义命令、自定义符号、链接。

自定义命令在会话工作目录中执行，结果默认缓存 0 秒（即每次刷新都执行）；可通过配置调整超时、最大宽度和是否保留 ANSI 颜色。命令走系统默认 shell（Windows 为 `cmd.exe`，其他平台为 `/bin/sh`）。

### 布局（2）

分隔符、弹性分隔符。

终端较窄时，渲染会优先保留左侧内容，从右侧开始整块丢弃优先级最低的组件（例如 Token、缓存命中率），而不是把文字截断成省略号。

## 配置文件

默认路径：

```text
~/.pi/agent/me-tui.json
```

首次启动会自动创建。配置包含版本号、语言、图标、颜色级别、行/组件、Powerline、全局样式、缓存与刷新设置。

## 与其他 footer 扩展共存

Pi 同一时间只显示一个 footer。`pi-open-tui` 也会安装 footer；如果两个扩展同时启用，最后安装的生效。

本扩展不会自动禁用 `pi-open-tui`。打开 `/me-tui` 时会主动重新安装自己的 footer，因此在配置后通常显示 pi-me-tui。如果希望固定使用其中一个，可在 `pi config` 中禁用另一个，或设置：

```json
{
  "enabled": false
}
```

## 开发

```bash
npm install
npm run check      # 类型检查 + 测试
npm pack --dry-run # 查看将要发布的文件
pi -e .            # 在 Pi 中加载本地代码
```

测试覆盖配置归一化、Git 解析、Token/速度计算、渲染、组件注册和 TUI 基础交互。CI 在 Linux 和 Windows 上用 Node 22/24 跑同样的检查，细节见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 说明

- Vim 模式组件按需求暂缓，本版本不安装自定义编辑器
- Git PR / CI 组件按需求暂缓；当前环境没有 `gh`/`glab`
- 所有 Git、Token、速度数据均为本地计算，不发送网络请求
- 需要 Pi 1.0+ 与 Node 22.19+
